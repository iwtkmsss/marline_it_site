# Контекст проєкту

Оновлено: 2026-11-16.

## Підтверджено

- У цій директорії будемо спочатку проєктувати, а потім реалізовувати сайт ІТ-компанії.
- Назва компанії — **Marline**; мова першого макета — **українська**.
- Пропозиція компанії: розробка проєктів різного рівня складності для різних видів бізнесу, занурення у бізнес-процеси, їх автоматизація й оптимізація.
- Головний персонаж у верхній частині сайту — піксельна Мерилін Монро з анімаціями.
- Плавні, логічно пов'язані анімації та переходи — один із головних пріоритетів дизайну.
- Користувач має візуально бачити, який макет виходить.
- Процес має дозволяти точкові зміни окремих елементів і блоків.
- Має бути можливість попросити асистента повністю переробити макет.
- Для макета обрано Figma: користувач хоче самостійно рухати елементи та змінювати їх, а також просити асистента вносити правки.
- 2026-11-16 користувач обрав напрям **A** як ближчий і дозволив продовжувати роботу.
- Для HTML/CSS і клієнтського JS користувач попросив застосовувати `modern-web-guidance`. Політика підтримки браузерів: сучасні API плюс невеликі локальні fallback, без сторонніх пакетів/поліфілів (явний вибір користувача).
- На питання про дію «Обговорити проєкт» відповів: «поки заглушкою потім подумаєм». Контактний блок лишається заглушкою; не вигадувати контактів і не імітувати надсилання заявки.
- Поточний етап — розвиток напряму A в основну локальну frontend-версію сайту; демо A/B зберігаються для порівняння.

## Процес проєктування

### Стек — 2026-11-24

Користувач: сайт має бути на React, і так мало бути від початку. Обрано Next.js зі статичним експортом, з пакетів лише Next.js і React, анімації лишаються на CSS. Motion+ не купуємо. Ідеї можна брати з motion.dev і animejs.com, код пишемо власний.

### Живі сцени — рішення 2026-11-23

- Користувач погодив сюжет «один знімальний день» («так залишаємо»).
- Головне на сайті — анімації та «живі картинки»; з ідеї треба вичавити більше. Користувач готовий зробити скільки завгодно кадрів.
- Розподіл: **Codex лише генерує картинки й кадри анімації**, **увесь код робить Claude**.
- Від старих фото й анімацій можна відмовитися й переробити все з нуля, якщо це потрібно.
- План і промпти — [design/live-scenes/BRIEF.md](design/live-scenes/BRIEF.md): прокрутка «перемотує» дію героїні в кожній сцені, плюс реакції на відкриття запитань і послуг. Пробу з новою героїнею (0a, 0b, 5a) користувач відхилив: обличчя вийшло значно гіршим. Рішення: лишаємо теперішню героїню й стиль, перший екран без змін, нові кадри генеруються з референсом `assets/mascot/marilyn-scenes.webp`. P1 — 44 кадри, P2 — 16. Пілот — цикл ходи 5a. Сирі файли кладуться в `assets/story/raw/`; вихідні кадри для ескізів 3b уже вирізані туди.

### Сторінка як історія — «один знімальний день», 2026-11-23

Користувач попросив переробити дизайн як історію: кожен екран — наступний момент, фон змінюється при прокрутці, логіка має бути зрозумілою й випливати з назви чи сенсу сайту. Запропоновано й реалізовано сюжет (ще не погоджений користувачем): Marline ≈ Marilyn, тож сайт — фільм про бізнес відвідувача. «Ваш бізнес — у головній ролі, ми — знімальна група.» П'ять сцен, світло від ранку до ночі, кожна сцена — етап процесу:

1. Гримерка — hero (wow-сцена без змін), теплий ранковий фон.
2. Читка сценарію — «Занурюємося»; FAQ оформлено як сторінку сценарію (Courier, репліки «Ви» / «Marline»).
3. Розкадровка — «Проєктуємо»; кресленна сітка, макет цього сайту як три кадри розкадровки, персонаж указує на них.
4. Знімальний майданчик — «Розробляємо»; темна сцена з прожектором, послуги як «Що знімаємо».
5. Прем'єра — «Розвиваємо» + контактна заглушка; ніч, лампи афіші, персонаж іде в арку.

Кожну сцену відкриває хлопавка («Сцена N»), яка «клацає» при появі. Фіксована кіноплівка зліва (≥1200 px) показує поточну сцену. Фон — фіксований шар із CSS view timelines (кросфейд кольору лишається й у reduced motion); fallback у `src/story.js` через IntersectionObserver; без JS кожна сцена має власне тло. Вкладки процесу прибрано — етапи стали самими сценами. Перевірено 1440/768/390/320 px без горизонтального переповнення, перемикання фону, перехід за плівкою й `aria-current`, `npm run check`, `npm run build`, консоль без помилок. Fallback-гілку без підтримки view timelines і screen reader окремо не перевіряли.

### Основна локальна версія A — 2026-11-16

Розвинено кореневу сторінку `index.html` із `src/site.css`, `src/site.js`, `src/motion.js`: hero з піксельною появою персонажа, рішення на native details, інтерактивні етапи роботи, FAQ й контактна заглушка. Шрифти Unbounded/Golos Text зберігаються локально. Поточна презентаційна реалізація — статичні HTML/CSS/JS без runtime-залежностей; збірка `npm run build` формує лише публічні файли в `dist/`. Перегляд: http://127.0.0.1:8473/.

Використано `modern-web-guidance` та обрану користувачем політику fallback. Декоративна прокрутка працює через CSS scroll timelines, а за відсутності підтримки лишається статичною. Details мають native миттєве розкриття без нових CSS API; меню й вкладки отримали невеликі локальні fallback. Режим меншого руху залишає завершений портрет і кольоровий зворотний зв'язок.

Перевірено 320/390/768/1440 px, меню/Escape/фокус при зміні ширини, розкриття details, клавіатурні вкладки, deep links і ручний reduced motion. `npm run check` та `npm run build` пройшли; зібрана сторінка відкрилася без console warning/error. Системний reduced motion і screen reader окремо не тестували. Хостинг, домен і контакти ще не визначені; нові файли наразі локальні. Ці зміни автоматично не оновлюють Figma.

### Вау-сцена, пробний етап — 2026-11-16

Користувач попросив прототипувати сцену, яку запропонував асистент: неслухняний тайл, погляд/кліпання, тайл стає на місце, піксель-естафета на першому скролі. Плюс ідея №3 «Цифровий вітер». Генератора зображень у сесії не було, тож кадри очей користувач обрав генерувати сам. Демо лежить у `design/wow-study/` (http://127.0.0.1:8473/design/wow-study/); основна сторінка не змінювалась. Поки кадрів немає, кліпання процедурне з оригінального PNG. Промпти для кадрів — `design/wow-study/frames/README.md`. Перевірено покадрово через `?debug` на 1440 і 390 px: кліпання, стрибок тайла, вітер, стрічка, естафета до вузла 01, ручний режим меншого руху, відсутність горизонтального переповнення й JS-помилок. Плавність наживо не перевірена: браузерна панель давала ~1 кадр/с. Того ж дня користувач додав згенеровані кадри `eyes-viewer/half/closed.png` (1254×1254, без зсуву відносно оригіналу); зоровий контакт подовжено до 0,85 с. Сцена разом зі стрічкою триває ~6–7 с, це більше межі WCAG 2.2.2; для production треба стиснути або додати паузу поруч. Відкрите питання: юридичний ризик образу Мерилін Монро для комерційного маскота (асистент радив перевірити до інвестицій у покадрову анімацію).

Оновлення 2026-11-16, друга половина дня:
- Користувачу не сподобалося складання з тайлів, бо воно виглядало шаблонно. Він обрав варіант «з одного пікселя». Тепер фіолетовий піксель росте й ділиться 1→4→16→64, далі квадродерево дрібнішає за деталями, і проступає портрет; триває 2 с.
- Блоковий вітер, коли волосся рухалося квадратиками, користувачу теж не сподобався. Тепер вітер складається з трьох згенерованих кадрів волосся користувача (`frames/hair-*.png`) з піксельним розчиненням між ними. Зірвані пікселі прибрано.
- Рішення: складання робимо кодом, рух волосся робимо кадрами.
- Пізніше користувачу не сподобалося, що складання починається з одного величезного квадрата, а наприкінці по краях вилазять зайві квадрати. Тепер піксель розходиться хвилею клітинок 8×8 лише в межах силуету, а краї діляться до найдрібнішого рівня ще до проявлення портрета.
- Користувач додав проміжні кадри вітру: rising, gust-2 і falling (промпти лежать у `design/wow-study/frames/README.md`).
- Після цього лишалися дві проблеми. Перша: наприкінці складання смикались краї. Причин було дві: квадрати під портретом прибиралися одним кадром, а canvas малював без згладжування, на відміну від `<img>`. Друга: порив складався з надто частих ривків між різними кадрами.
- Виправлення: квадрати тепер плавно гаснуть, а згладжування canvas збігається з `<img>`. Порив скорочено до 5 кадрів, переходи між ними тривають по 320 мс, і клітинки проявляються поступово. `hair-rebound` не використовується.
- Користувачу не сподобалися ні гасіння квадратів, ні морфінг кадрів. Рішення: анімацію після складання повністю малює Codex покадрово (01–04 погляд і кліпання, w01–w13 порив). Промпт лежить у `design/wow-study/frames/anim/CODEX_PROMPT.md`. Демо програє кадри як спрайт-анімацію з автовирівнюванням обличчя. Складання завершується без гасіння: дрібні клітинки по одній стають справжніми пікселями.
- Codex намалював усі 17 кадрів. Обличчя на них не зсунуте, вирівнювати не довелося. Найбільші стрибки між кадрами: w13→оригінал (локони відрізняються), w07→w08→w09 і w02→w03. Інші стрибки, якщо вони помітні наживо, виправляються лише перегенерацією кадрів.
- Користувачу не сподобалось, що кадри Codex гладкі, а оригінал квадратний, бо в кінці стиль перемикається. Оригінал намальований на сітці ≈8 px. Тепер код переводить змінене волосся кадрів на цю сітку, а незмінені блоки бере з оригіналу точно. Перехід від w13 до оригіналу клітинками прибрано, тепер це звичайна зміна кадру. Обробка кадрів іде у Web Worker, і сцена стартує приблизно за 0,4 с.
- Перехід від передостаннього кадру (w13) до оригіналу лишався надто різким: кадри w10–w13 відрізняються від оригіналу в 4–5 разів сильніше, ніж w01. Тепер волосся повертається тим самим шляхом: пік → w04 → w03 → w02 → w01 → оригінал. Кадри w07–w13 не використовуються, а друге кліпання малюється кадрами очей поверх.

### Попередні макети та дослідження

Макет проєктуємо у Figma з ручними правками користувача та правками асистента. Плагін Figma встановлений та увімкнений, але прямі інструменти Figma цьому чату не надані. Після входу користувача редактор відкрився через браузерний інтерфейс.

[Файл Figma — Marline, дизайн-концепція 01](https://www.figma.com/design/xJeIYybQAQ2NyIu0Qhplnr?node-id=3-2) містить чотири артборди: A — Головна / Desktop (1440 × 3000), A — Перший екран / Mobile (390 × 1120), B — Перший екран / Альтернатива (1440 × 1000), Рух — сценарій (1440 × 1280). Основний асистент переглянув експорти A, B й mobile; у Figma окремо перевірив native Text заголовка та прив'язані стилі й колірні змінні. За звітом Figma agent: 147 текстових шарів, 8 компонентів, 11 екземплярів, 8 колірних змінних, 7 текстових стилів; повний підрахунок root незалежно не повторював.

У сценарії руху є нативна інтерактивна демонстрація: 100 мс затримки + Smart Animate 1400 мс до персонажа, перехід до процесу за кліком 600 мс. Root перевірив параметри вступу в UI та відтворив перехід від портрета до процесу; макети A/B самі залишаються статичними. У Figma не реалізоване автоматичне врахування reduced motion. Сценарій зв'язку/надсилання заявки не визначено. На момент завершення роботи щоденний ліміт Figma AI вичерпаний; native manual editing доступне, підписку не змінювали.

Збережено локальну резервну копію [design/marline-concept-01.fig](design/marline-concept-01.fig) і PNG-прев'ю в [design/previews/](design/previews/).

Для перевірки руху створено окремий [design/motion-study/](design/motion-study/README.md), без framework, backend чи production-реалізації. Локальний перегляд: http://127.0.0.1:8473/design/motion-study/ при запущеному static server з кореня репозиторію. Портрет складається з crop-фрагментів за 1550 мс; пікселі пов'язують його зі схемою процесу на прокрутці. Root перевірив складання й завершений стан, ручний режим меншого руху, anchors, відсутність горизонтального переповнення на 1440, 390 і 320 px та відсутність повідомлень у console log. Системний reduced motion передбачено в CSS/JS, окремою зміною налаштування ОС не перевіряли. Google Fonts завантажились; без мережі є sans-serif fallback. Технологічний стек майбутньої production-реалізації ще не визначено.

## Запропонований напрям першої концепції

Користувач обрав напрям A як основу 2026-11-16. Деталі подальшої композиції та руху уточнюються під час розробки:

- Світле сріблясте тло, темна типографіка, фіалковий акцент, світлий бузковий і блідо-рожевий; червоний переважно в губах персонажа.
- Unbounded для заголовків і Golos Text для основного тексту, з підтримкою кирилиці.
- Основна композиція A: текст ліворуч, велика Мерилін праворуч; пікселі пов'язують портрет зі схемою бізнес-процесу нижче.
- Альтернатива B: сливова театральна сцена, центральний портрет перед великим світлим словом Marline.
- Окремий мобільний макет і сценарій руху з трьох фаз. Фактичні анімації треба перевірити окремо; storyboard не є доказом реалізованого руху.

Самодостатнє ТЗ: [design/BRIEF.md](design/BRIEF.md).

## Відкриті питання

- Відгук користувача про розвинену основну версію A, композицію та образ персонажа.
- Пріоритетні бізнес-сегменти й конкретні послуги для остаточних текстів.
- Наявний логотип, інші бренд-матеріали та реальні проєкти для майбутнього наповнення.
- Остаточна структура сайту, додаткові сторінки й контактний сценарій.
- Узгодження сценарію руху та майбутньої поведінки секцій після вибору напряму; у Figma перевірено лише демонстраційний вступ/перехід, у браузерному study — складання, scroll і ручний режим меншого руху.
- Майбутній хостинг, домен і контактний сценарій; для поточної презентаційної сторінки обрано статичні HTML/CSS/JS без runtime-залежностей.
