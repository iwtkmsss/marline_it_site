## Про проєкт

Сайт ІТ-компанії **Marline**, усі тексти українською. Користувач обрав світлий напрям **A**. Зараз його розвивають в основну статичну сторінку. Демо A/B у `design/motion-study/` треба зберегти для порівняння. Спершу дизайн погоджують з користувачем, і лише потім роблять production-реалізацію. Production-стек: Next.js зі статичним експортом (рішення користувача 2026-11-24). Хостинг і домен ще не обрано.

Незмінні вимоги користувача:
- Контактний блок поки лише заглушка. Не вигадуй контакти чи кейси й не імітуй надсилання заявки.
- Для HTML/CSS і клієнтського JS спершу застосуй скіл `modern-web-guidance` (цільовий search/retrieve), потім реалізуй.
- Використовуй сучасні веб-API з невеликими локальними fallback. З 2026-11-24 дозволено лише Next.js, React і React DOM; інших пакетів (зокрема Motion, anime.js) і поліфілів без згоди користувача не додавай. Ідеї з motion.dev і animejs.com брати можна, код пиши власний. Перевіряй підтримку API, а без неї сторінка має лишатися працездатною у статичному чи нативному вигляді.
- Тести для дрібних візуальних правок не додавай.
- Зміни в коді не синхронізуються з Figma автоматично ([файл](https://www.figma.com/design/xJeIYybQAQ2NyIu0Qhplnr?node-id=3-2), локальна копія `design/marline-concept-01.fig`).

## Команди

npm-пакети не потрібні. Для серверів потрібен Python, для перевірки й збирання потрібен Node.

```bash
npm run dev       # статичний сервер з кореня: http://127.0.0.1:8473/ (motion study: /design/motion-study/?version=a|b)
npm run check     # node --check для src/site.js, src/motion.js, scripts/build.mjs
npm run build     # копіює фіксований перелік публічних файлів у dist/
npm run preview   # сервер лише для dist/: http://127.0.0.1:8474/
```

Автотестів немає. Перевірка складається з `npm run check`, `npm run build` і візуальної перевірки в браузері. Зазвичай перевіряють ширини 320/390/768/1440 px без горизонтального переповнення, меню, Escape і фокус, клавіатуру у вкладках, deep links, reduced motion та відсутність помилок у console. Синтаксис motion study перевіряй так: `node --check design/motion-study/motion.js`.

## React-версія (`web/`) — основна

Нові зміни робимо в `web/`. Статична версія в корені (`index.html`, `src/`) — зразок для порівняння.

```bash
cd web
npm install
npm run dev       # http://127.0.0.1:8475
npm run build     # статичний сайт у web/out/
npm run preview   # http://127.0.0.1:8476, потребує Python
```

- `app/layout.jsx` підключає стилі `web/styles/` у порядку fonts → site → wow → marline → story; `app/page.jsx` складає секції з `components/`. Усі тексти списків — у `lib/content.js`.
- `scripts/sync-public.mjs` копіює фіксований список публічних файлів з `assets/` у `web/public/assets/` (не в git). Новий публічний файл додай туди.
- `components/Header.jsx` вимірює рядок навігації й перемикає інлайн/popover. `Backdrop.jsx` має fallback фону. `Works.jsx` — діалог макета. Діорама — чистий CSS.
- Головна (`/`) показує ASCII-портрет: `components/AsciiPortrait.jsx`, `lib/ascii-scene.js` + `ascii-shaders.js` (WebGL2: 13 ракурсів × 4 шари, рух голови, кліпання, погляд без курсора). Ресурси збирає `design/ascii-study/build.py`. `lib/ascii-dissolve.js` під час прокрутки розсипає символи й складає з них першу картинку діорами; годинник — лише позиція прокрутки, завершується за 80 px до секції (відступ якоря). Без WebGL, у reduced motion чи без закріпленої діорами лишається звичайний перехід.
- `/pixel` — попередній піксельний портрет для порівняння. `lib/hero-scene.js` — його рушій (порт `wow.js`). Він працює з вузлами за id (`Hero.jsx`, перемикач руху у `Footer.jsx`), тому React не має їх перерендерювати.
- Мініфікатор скорочує `animation-range`; після змін перевіряй обчислені діапазони у зібраній версії.

## Архітектура статичної версії

Основна сторінка складається з `index.html`, стилів `src/site.css` → `design/wow-study/wow.css` → `src/marline.css` → `src/story.css` (саме в такому порядку) і скриптів `src/site.js`, `src/story.js` та `design/wow-study/wow.js` (hero-сцена; `src/motion.js` сторінка вже не підключає). Порядок сторінки: перший екран (hero, рівно 100svh) → закріплений блок «Як ми працюємо» з піксельною діорамою бізнесу (`#process`) → нічні секції `.act-night`: «Що ми робимо» (`#solutions`), «Цей сайт: від макета до сторінки» (`#works`), «До першої розмови» (`#questions`, запитання як сторінка сценарію), контакт-заглушка (`#contact`). Скрипти підключено з `defer`, кожен працює як самостійний IIFE без модулів. Шрифти лежать локально в `assets/fonts/` разом з OFL-ліцензіями. Motion study натомість бере шрифти з Google Fonts.

Сторінка спирається на нативні можливості, а JS лише покращує поведінку:
- **Меню** — це `popover="auto"` з `popovertarget`. `site.js` синхронізує `aria-expanded`, закриває меню на Escape чи кліку поза ним і перемірює навігацію при resize. Для браузерів без `:popover-open` є fallback (`@supports selector(:popover-open)` у CSS).
- **Акордеони** (`details[data-accordion]`) розкриваються нативно. Плавне розкриття ввімкнене лише під `@supports selector(details::details-content) and (interpolate-size: allow-keywords)`.
- **Шапка** фіксована й компактна. Після першого екрана `story.js` ставить їй `data-solid` (світлий напівпрозорий фон, читається на будь-якій секції).
- **Блок процесу — діорама** (`#process`): `.process-pin` (420svh, `view-timeline: --process`) містить sticky `.process-scene` на 100svh: ліворуч чотири кроки, які змінюють один одного, праворуч `.diorama` з чотирма шарами-станами `.dio-1`…`.dio-4`. Наступний стан відкриває `clip-path: inset()` разом із променем `.scan-beam` (діапазони contain 22–30, 47–55, 72–80 %). Кадри D1–D4 лежать у `assets/story/diorama/` (`dN.webp` 1600 px і `dN-800.webp`), сирі — в `assets/story/raw/diorama/`. Вони вантажаться наперед (`eager`, `fetchpriority="low"`), бо з `lazy` промінь проходив раніше за картинку. ТЗ і промпти — `design/live-scenes/DIORAMA.md`. Без підтримки, у reduced motion або при висоті <520 px закріплення вимикається: кроки списком, поруч сітка з усіх чотирьох станів. Посередині сцени (contain 48–50 %) сторінка темніє разом із діорамою: таймлайн `--dusk` на тому самому `.process-pin`, текст кроків 3–4 кремовий. Фон сторінки використовує окремий таймлайн `--day`, щоб не конфліктувати з `--process`.
- **Фон**: кожна секція має власне тло (`--act-bg`). Де є view timelines + `timeline-scope`, фіксований `.backdrop` кросфейдить шари: день на вході в `#process` (`--day`), ніч на вході в `#solutions` (`--night`); без підтримки `story.js` додає `html.backdrop-fallback` і перемикає шари через IntersectionObserver. Правила з `animation-timeline` пиши з не меншою специфічністю, ніж шорткат `animation`, інакше таймлайн скинеться.
- **Блок «Цей сайт»**: перший макет (`design/previews/a-desktop.png`, відкривається в `dialog`) і знімки теперішнього сайту `assets/works/site-hero.webp`, `site-mobile.webp`. Їх зроблено headless Edge із `--force-prefers-reduced-motion`; після помітних змін першого екрана їх варто перезняти. Мобільний знімок — на 500 px, бо вужчого вікна headless Edge не робить.
- **Рух hero** (`wow.js`, форк `motion.js`): при першій появі піксельний портрет складається на `<canvas>` поверх `<img>`, далі погляд і порив вітру кадрами. Після цього canvas ховається, а loop зупиняється. Кнопок керування анімацією на першому екрані немає: наведення чи клік по портрету запускає порив вітру. Прокрутка ніколи не перехоплюється. Вступ стає на паузу, коли вкладку приховано.
- **Reduced motion**: системний `prefers-reduced-motion` має пріоритет. Ручний перемикач «Менше руху» (`#motion-toggle`) виставляє `data-reduced-motion="true"` на `<html>`. Тоді лишається завершений портрет і кольоровий зворотний зв'язок.
- **Зв'язок між скриптами** відбувається через кастомні події на `document`. `site.js` надсилає `marline:layoutchange` при зміні висоти, наприклад коли розкривається акордеон, і `motion.js` перемірює траєкторію. `marline:motionchange` змушує `site.js` завершити поточні переходи станів. Додаючи елементи, які змінюють висоту, надсилай `marline:layoutchange`.

`scripts/build.mjs` використовує лише вбудовані API Node. Він копіює явний список `publicFiles` у `dist/`, тож **новий публічний файл (asset, скрипт, шрифт) треба додати в цей список**, інакше його не буде в збірці. Скрипт спершу перевіряє й читає всі джерела, а вже потім очищає `dist/`. Він відмовляється чистити шлях, якщо той відрізняється від `<root>/dist` або містить symlink чи junction. Цих запобіжників не послаблюй. `design/`, документація і промпти до збірки потрапляти не мають.

Інше:
- `design/BRIEF.md` — початкове ТЗ концепції.
- `design/previews/` — PNG-прев'ю з Figma.
- `assets/mascot/` — PNG персонажа (ще не оптимізований і не затверджений як фінальний бренд-актив) і промпт його генерації.
